Recap of the key concepts

$$\underbrace{\delta_t}_\textrm{prediction error} = \underbrace{o_t}_\textrm{outcome} - \underbrace{p_t}_\textrm{model prediction} \tag{Equation 1}$$
$$\underbrace{p_{t+1}}_\textrm{new prediction} = \underbrace{p_t}_\textrm{old prediction} + \underbrace{\alpha \delta_t}_\textrm{scaled prediction error} \tag{Equation 2}$$
$$\underbrace{u}_\textrm{utility} = \underbrace{m}_\textrm{reward magnitude} \times \underbrace{p}_\textrm{reward probability} \tag{Equation 3}$$
$$\underbrace{P(c_1)}_\textrm{probability of choosing option 1} = \frac{1}{1+ e^{-\beta(u_1 - u_2)}} \tag{Equation 5}$$

But how do we know α and β?

Simulating. Choose α and β, then set each choice to option 1 or option 2 depending on whether a random number falls below the choice probability.

Fitting. Vary α and β until the model comes as close as it can to the choices that were actually made.

Why simulate at all, when we have real data?

With simulated data we know the ground truth. We set α ourselves, so we can check whether fitting gets it back.

With real data we never know it. All we have is an estimate, and no way to check it against the truth — which is exactly why the simulations come first.

If the recovery fails, the experiment needs changing before anyone is recruited — not after.

A different way to fit the same idea: regression

The learning model weights the last outcome by α and discounts each earlier one by a further factor of $(1-\alpha)$. A regression estimates one weight per lag freely, instead of forcing them onto this curve.

Recap: why are simulations important?

The task finds the effect when it is there, and does not invent one when it is not. Without both halves, a result on the real data means very little.

Recap: what we are not using simulations for

  • Not to judge how similar the simulated data look to the participants'
  • Not to be merged with the participants' data, or reported as data
  • Only to validate the paradigm, before and alongside the real analysis

It is circular, but in a useful direction: nothing here is used to support a cognitive claim. If the circle fails to close — if we cannot recover what we put in — the paradigm or the analysis needs work.

For what reasons could recovery or falsification fail?

  • Too few trials — say 20 stable and 20 volatile
  • Too little or too much variance in what matters — only stable blocks, or a volatile block that switches every 5 trials

How do we evaluate a fit? The log likelihood

$$\underbrace{\log L}_\textrm{log likelihood} = \sum_{t} \log \underbrace{P(c_t \mid \alpha, \beta)}_\textrm{probability the model gave the observed choice}$$

Maximise this, or multiply by $-1$ and minimise the negative log likelihood instead — the same thing.

Discuss
  • Which trials dominate that sum — and why is that a good thing?

Why not always use grid search?

  • Most of the work goes into parts of the parameter space that are obviously wrong
  • It becomes intractable quickly: 100 combinations for two parameters is 10,000 for four
  • There are ways to find the maximum without measuring every point
  • Those ways can get stuck in a local maximum, so they are run from several starting points

One intuitive trick: gradient ascent

Start somewhere, work out which way is uphill, take a step, repeat. This is what the notebook's fitting routine does — from ten starting points, keeping whichever run ends highest.

Models that are not nested: the BIC

$$\textrm{BIC} = k \log (n)- 2 \log (\textrm{likelihood}) \tag{Equation 8}$$
  • A trade-off between goodness of fit and the number of parameters $k$
  • Smaller is better
  • No p-value: a heuristic, not a test
Discuss
  • What did the BIC suggest?

Model comparison: pros and cons

  • AIC $= 2k - 2 \log (\textrm{likelihood})$ can overfit, and prefer models more complex than they need to be
  • BIC $= k \log (n) - 2 \log (\textrm{likelihood})$ penalises complexity more as the sample grows — already more than AIC once $n \geq 8$ — so it usually prefers simpler models, and sometimes underfits
  • Both are crude but a reasonable start. Try both; they often agree. When they do not, it is a judgement call — plot the parameters and the fits
  • If two models have the same number of parameters, compare log likelihoods directly, or use a likelihood ratio test if they are nested
  • Cross-validation is another option, not covered here

Inspecting the parameters: additive utility

Additive utility adds $\omega$, the weight on magnitude. An $\omega$ pinned at 0 or 1 says the participant used only one of the two dimensions — only the probabilities, or only the reward magnitudes.
